# II. RESUMEN DEL PROYECTO

QUILLAYAA! es una propuesta de plataforma web orientada a la gestión de pedidos de comida y bebidas en la ciudad de Quillabamba. El proyecto busca facilitar la interacción entre clientes, negocios y repartidores mediante un sistema que permita consultar establecimientos, visualizar productos, realizar pedidos, gestionar pagos y coordinar el servicio de delivery.

El proyecto toma como caso de estudio a **Quilla Morro**, establecimiento dedicado a la venta de comidas rápidas, bebidas frías y bebidas calientes. En el contexto actual, parte de la gestión de pedidos puede realizarse mediante procesos manuales, como el uso de comandas de papel, mientras que los pagos pueden efectuarse mediante efectivo y billeteras digitales.

QUILLAYAA! plantea centralizar estos procesos mediante una plataforma digital.

Una característica importante del proyecto será su **diseño responsive**, permitiendo que la plataforma sea utilizada desde computadoras, laptops, teléfonos Android, iPhone, tablets Android e iPad mediante navegadores web compatibles.

---

# III. DESCRIPCIÓN DEL PROBLEMA

## 3.1 Realidad problemática

En Quillabamba existe una variedad de negocios dedicados a la comercialización de alimentos y bebidas, entre ellos restaurantes, pollerías, cevicherías, cafeterías, pastelerías, chifas, pizzerías y establecimientos de comida rápida.

Los procesos de atención y recepción de pedidos pueden variar entre cada negocio. En determinados casos se utilizan mecanismos tradicionales, como llamadas, mensajes, atención presencial o registros manuales mediante comandas.

Esta situación puede dificultar la organización de los pedidos, especialmente cuando aumenta la cantidad de clientes o cuando es necesario coordinar simultáneamente productos, pagos y entregas.

Como caso de estudio se considera a Quilla Morro, donde se identifican necesidades relacionadas con la gestión organizada de pedidos, productos, pagos y entregas.

A partir de esta situación se plantea el desarrollo de QUILLAYAA!, una plataforma web orientada a centralizar estos procesos.

---

# IV. PLANTEAMIENTO DEL PROBLEMA

## 4.1 Problema general

¿Cómo mejorar la gestión de pedidos de comida y bebidas de los negocios de Quillabamba mediante una plataforma web responsive accesible desde diferentes dispositivos?

## 4.2 Problemas específicos

* Gestión manual de determinados procesos relacionados con los pedidos.
* Dificultad para consultar diferentes negocios y sus productos desde una plataforma centralizada.
* Falta de un proceso digital integrado para registrar y controlar pedidos.
* Necesidad de organizar los diferentes estados de un pedido.
* Necesidad de gestionar los pagos asociados a los pedidos.
* Dificultad para coordinar el servicio de delivery cuando un negocio no dispone de repartidores propios.
* Necesidad de contar con una plataforma accesible desde diferentes dispositivos.

---

# V. JUSTIFICACIÓN

## 5.1 Justificación tecnológica

QUILLAYAA! permitirá aplicar tecnologías de desarrollo web para digitalizar procesos relacionados con negocios de comida y bebidas.

La plataforma integrará diferentes módulos dentro de un mismo sistema, permitiendo gestionar usuarios, negocios, productos, pedidos, pagos y delivery.

Además, se utilizará un diseño responsive para adaptar la interfaz a diferentes tamaños de pantalla.

## 5.2 Justificación práctica

La plataforma busca facilitar el proceso de pedido tanto para los clientes como para los negocios.

El cliente podrá consultar productos, seleccionar lo que desea adquirir y realizar un pedido.

El negocio podrá administrar sus productos y recibir los pedidos realizados mediante la plataforma.

Cuando el negocio no cuente con personal propio para realizar una entrega, podrá utilizar el componente de delivery de QUILLAYAA!, mediante repartidores registrados.

## 5.3 Justificación local

El proyecto está orientado específicamente al contexto de Quillabamba. Por ello, la solución considera las características de los negocios locales, los medios de pago utilizados y la disponibilidad de personas que pueden realizar servicios de entrega mediante motocicletas o mototaxis.

# IX. FLUJO GENERAL DEL SISTEMA

El proceso principal de QUILLAYAA! será:

**Cliente**

→ Ingresa a QUILLAYAA!
→ Selecciona un negocio
→ Consulta productos
→ Selecciona productos
→ Agrega productos al carrito
→ Confirma el pedido
→ Registra/selecciona dirección
→ Selecciona método de pago
→ Confirma pedido
→ El negocio recibe el pedido
→ El negocio acepta y prepara el pedido
→ El pedido pasa a estado listo
→ Se asigna delivery cuando corresponda
→ El repartidor recoge el pedido
→ El repartidor realiza la entrega
→ El pedido se marca como entregado.

---

# X. ESTADOS DEL PEDIDO

Para representar el proceso real se plantea utilizar diferentes estados:

| Estado             | Descripción                                         |
| ------------------ | --------------------------------------------------- |
| **Pendiente**      | Pedido registrado y esperando confirmación          |
| **Confirmado**     | El negocio aceptó el pedido                         |
| **En preparación** | El negocio está preparando los productos            |
| **Listo**          | El pedido está preparado para ser recogido          |
| **En camino**      | El pedido fue entregado al repartidor               |
| **Entregado**      | El cliente recibió el pedido                        |
| **Cancelado**      | Pedido cancelado según las condiciones establecidas |

---

# XI. SERVICIO DE DELIVERY

El sistema contempla dos situaciones.

### Caso 1: El negocio tiene repartidor propio

El negocio puede gestionar directamente la entrega.

### Caso 2: El negocio no tiene repartidor

QUILLAYAA! podrá utilizar repartidores registrados en la plataforma para realizar la entrega.

Este componente permite que personas interesadas en trabajar como repartidores puedan registrarse y participar en el servicio de delivery.

El flujo sería:

**Pedido listo**

→ búsqueda/asignación de repartidor
→ repartidor acepta
→ recoge pedido
→ realiza entrega
→ confirma entrega.

---
